# datagrep UX & Baseline-Feature Reference Study

**Purpose:** not another feature matrix — a look-and-feel reference plus a ranked, concrete gap list against datagrep's current state (as of 2026-08-08). Intended to be handed directly to implementation agents. All claims are cited; anything the research could not verify from docs/screenshots/issue trackers is flagged explicitly as **unverified** rather than guessed.

**Apps studied in depth:** TablePlus, DataGrip, DBeaver, Beekeeper Studio, Postico 2, Sequel Ace, MongoDB Compass, RedisInsight.
**Apps studied lightly (distinctive-pattern only):** Querious, Navicat, TableCruncher, Outerbase, Antares, Harlequin, rainfrog.

## 1. Sidebar / Navigation

| App | Tree shape | Huge-schema handling | Connections vs. objects | Connection color |
|---|---|---|---|---|
| **Postico 2** | Servers ("Favorites") → databases → schema-grouped tables/views (no dedicated Views subfolder — [open request](https://github.com/jakob/Postico/issues/285)) | Sidebar filter (⇧⌘F), quick-jump (⌘P). No evidence of thousands-of-tables handling — likely absent. | Separate: connect to a Favorite, then drill into databases/schemas. "Never more than two clicks away." | Yes — red=prod/green=dev convention, tints status bar/tab. Explicit accident-prevention framing. |
| **TablePlus** | Connections rail + databases column + objects tree (Tables/Views/Functions/Favorites/History/Recent-5) | Fuzzy search box + global ⌘P "Open Anything." **Fails badly at real scale**: 30 min to index autocomplete across 100+ schemas, unresponsive until 300-schema cache completes, 20s+ input lag at 100k tables ([#3649](https://github.com/TablePlus/TablePlus/issues/3649) area). Root cause: autocomplete indexing shares a queue with query execution and blocks it. | Separate: ⌘⇧K switch connection, ⌘K switch database (two-level rail). | Yes — color + tags (Local/Testing/Dev/Staging/Prod) + folder grouping. Explicitly marketed as mistake-prevention. |
| **DataGrip** | Data Sources → schemas → per-type object folders (toggleable flat/grouped) | Layered: opt-in schema selection (unselected schemas aren't even introspected), regex object filters, tree speed-search, and a global **Search Everywhere** (double-Shift) modal with `/tables film`-style scoped search. [Blog](https://blog.jetbrains.com/datagrip/2022/08/08/not-all-databases-schemas-are-displayed-by-default-why/) | Separate: Data Sources are the explicit top-level abstraction, groupable into folders. | Yes — right-click → Tools → Set Color, scoped to editor tabs/tree/etc. Simple, well-liked model. |
| **DBeaver** | One flat navigator tree; connections are literal top-level nodes | **Simple/Advanced/Custom view** toggle hides "complex meta-objects" down to just tables+views. Filter bar. Tree itself **paginates** — "elements fetch size" loads N children per level, "load more" on demand. | Not separate — connections are just tree nodes. | Yes, but via **Connection Type** (a bundled color+behavior profile, not a pure color picker) — DBeaver's own team was, per [GitHub discussion #38588](https://github.com/orgs/dbeaver/discussions/38588), moving toward something closer to DataGrip's simpler model. Standing bug: navigator color doesn't always match ([#5705](https://github.com/dbeaver/dbeaver/issues/5705)). |
| **Beekeeper Studio** | Switchable top-level sections (Tables / Queries / History), not one merged tree | Filter box w/ wildcards; app-wide ⌘P fuzzy search. **No connection folders** ([#1602](https://github.com/beekeeper-studio/beekeeper-studio/issues/1602)). **No multiple simultaneous connections in one window** — flagged as a real gap vs. DataGrip/Workbench ([#576](https://github.com/beekeeper-studio/beekeeper-studio/issues/576), open since 2021). | Weak separation — see #576 above; tabs aren't clearly tied to which connection they belong to. | Yes — label color shown in the statusbar and connection list. |
| **Sequel Ace** | Pre-connect: Favorites list (separate window). Post-connect: flat table/view list, no favorites visible alongside it. | Name-only filter box, no content search ([discussion #1514](https://github.com/Sequel-Ace/Sequel-Ace/discussions/1514)). | Separate: each connection is its own OS window (⌘N). | Yes, but **downgraded from a full tab-fill color (Sequel Pro) to a small dot on the tab edge**, and users revolted ([#1013](https://github.com/Sequel-Ace/Sequel-Ace/issues/1013)): *"I think this is a huge step back, and really confusing when I have multiple tabs open, especially when dealing with production environments."* The dot also **only appears with 2+ connections open** — a single window has zero color indicator. **Lesson: make it a large, always-visible surface.** |
| **MongoDB Compass** | Connections → Databases → Collections, one disclosure level at a time | Since v1.44 multiple live connections coexist in the sidebar. **Scale failure**: 10,000+ databases / 400,000+ collections took **60+ seconds** to become usable because stats were eagerly preloaded for the whole tree with no virtualization — patched by batching stat updates ([PR #2618](https://github.com/mongodb-js/compass/pull/2618)). | Separate — right-click context menu on the connection row for connect/disconnect/duplicate/etc. | **Best model found**: connection color becomes the **background of every tab opened against it** — prod (red) is visually distinct from staging (orange) at all times, not just in the sidebar. |
| **RedisInsight** | List View (flat, `SCAN`-paginated) or **Tree View** (auto-groups keys into folders by `:`-delimited namespace, since v2.0.5) | Deliberately resists "load everything" — `SCAN` batches (default `COUNT 200`), "Scan More" only. Requests for "Scan All" are **actively declined** by maintainers due to OOM risk ([#526](https://github.com/redis/RedisInsight/issues/526), 26 comments, still open). Maintainer-benchmarked: SCAN cost is dominated by round-trip latency, not match count — 1.3M keys took 1.5s locally but **9 minutes over an 88ms-RTT SSH tunnel** ([#6202](https://github.com/redis/RedisInsight/issues/6202)). **Directly validates datagrep's prefix-required Redis design.** | Top-level databases list, auto-discovers local Redis. | **No connection color-coding exists** — open request since at least [#2911](https://github.com/redis/RedisInsight/issues/2911), no ETA. Gap datagrep could beat them on. |

**Cross-cutting lesson for datagrep's sidebar:** every app with a huge-schema failure mode failed the same way — *eager, blocking, whole-catalog work* (TablePlus's autocomplete cache, Compass's stat preload). Every app that avoids it does so via **opt-in scope** (DataGrip's schema selection) or **paginated/lazy tree loading** (DBeaver's fetch-size, RedisInsight's SCAN batching). datagrep's lazy-per-level tree design is already aligned with the winning pattern — see §8 for the one thing still missing (partial-view visibility).

## 2. Schema/Object Detail View

**Default tab/view on first opening a table**, and how structure info is organized:

| App | Default view | Structure organization |
|---|---|---|
| Postico 2 | **Content** (data grid) | **Unified single Structure editor** — columns, indexes, and constraints together, "so you see everything at once" ([marketing copy](https://eggerapps.at/postico2/), corroborated by an App Store review specifically praising "the nice UX for editing a table's indexes"). Separate DDL view shows a **three-way diff** (current / pending / resulting) when a structure change is uncommitted — a genuinely distinctive migration-preview pattern. |
| TablePlus | **Data** (300 rows/page) | Structure view (bottom toggle, ⌘⌃]) shows columns with all attributes inline; indexes managed from an adjacent Index manager; FKs set at column level. No confirmed dedicated DDL tab — SQL appears to be a pending-change **preview**, not a persistent read view. |
| DataGrip | **Data grid**, in "Table" view-mode (switchable in-tab to Tree/Text/Transpose — Tree recommended for JSON/array columns) | **No fixed Data/DDL/Diagram tab strip** — DDL and ER diagrams are separate tabs you open on demand (Ctrl+Alt+U for diagrams), not persistent per-table tabs. This contradicts a common assumption; confirm before copying "DataGrip has tabs" as a pattern. |
| DBeaver | **Properties** (structure) — confirmed default; a filed bug ([#12093](https://github.com/dbeaver/dbeaver/issues/12093)) exists specifically because the editor sometimes fails to default to Properties, confirming it's the intended behavior. | Persistent tab strip: **Properties / Data / Diagram**, the closest match to a classic "tab strip per object" model if datagrep wants that shape. |
| Beekeeper Studio | **Table View** (data grid, "Excel-like") | Right-click → **View Structure**, sectioned into **Columns / Indexes / Relations / Triggers**. Indexes/Relations disabled until the table exists (during creation). |
| Sequel Ace | Confirmed fixed shortcut-bound tabs: **⌘1 Structure, ⌘2 Content, ⌘3 Relations, ⌘4 Triggers, ⌘5 Info, ⌘6 Custom Query**. No separate Indexes tab — folded into Structure/Info. Which tab opens by default on a table click is **unverified**. |
| MongoDB Compass | **Documents** | Tabs: **Documents / Aggregations / Schema / Explain Plan / Indexes / Validation**. The **Schema tab is the standout idea** — see §3 for detail, it's the best-in-class answer to "how do you summarize a field with mixed/nested types." |
| RedisInsight | Right-side **detail panel**, not a tab strip — per-Redis-type rendering (String/Hash/List/Set/ZSet/Stream/JSON), each with type-appropriate editing affordances. |

**Recommendation for datagrep's in-flight schema pane:** Postico's unified single-view (columns + indexes + constraints together) is the pattern people spontaneously praise by name, and it's a better fit for a side-panel/inspector than DBeaver's or Sequel Ace's tab-fragmented approach. datagrep's current interaction model (single-click for schema info in a side panel, double-click for data) is actually a **third pattern** none of the primary competitors use in quite this form — most of them make Data vs. Structure a mode-switch on the *same* opened object rather than two different click actions. This can be a genuine differentiator (schema info is more discoverable, doesn't require navigating away from data), but only if the side-panel content itself follows Postico's "everything unified" philosophy rather than fragmenting into sub-tabs. Include: columns, indexes, constraints/FKs, and a plain read-only DDL view (cheap, high-value, requested implicitly by every app that has one).

## 3. Results Grid

**NULL vs. empty string vs. absent** — this is a trust surface, not cosmetic, and it is where the *most* competitors have shipped real, filed bugs:
- DBeaver renders NULL as literal `[NULL]` text, but has a filed bug where it shows `[NULL]` for *all* string values incorrectly ([#8803](https://github.com/dbeaver/dbeaver/issues/8803)).
- Beekeeper Studio has open bugs for **false-NULL display on populated columns** ([#2652](https://github.com/beekeeper-studio/beekeeper-studio/issues/2652)) and **exporting NULL as the literal string `"null"`**, corrupting numeric columns in spreadsheets ([#2863](https://github.com/beekeeper-studio/beekeeper-studio/issues/2863), [#571](https://github.com/beekeeper-studio/beekeeper-studio/issues/571)).
- Sequel Ace's NULL label rendered **invisible (black-on-black) in dark mode** ([#1415](https://github.com/Sequel-Ace/Sequel-Ace/issues/1415)).
- Postico's default behavior — **erasing a field's text sets it to NULL, not empty string** — is a persistent, still-open source of user confusion and accidental NOT-NULL violations ([#406](https://github.com/jakob/Postico/issues/406), [#407](https://github.com/jakob/Postico/issues/407)).
- DataGrip's exact NULL glyph/styling could not be verified from docs — flagged unverified by the research, not confirmed superior.

**datagrep already renders NULL / empty-string / ABSENT as three visually distinct states — this is ahead of the field.** No competitor studied cleanly nails all three; most only distinguish NULL vs. non-null and get that wrong under dark mode or export. Treat this as a real differentiator, but explicitly QA it against the two documented failure modes above (dark-mode contrast, and future CSV/export string-corruption) before shipping export.

**Nested value rendering** — three strategies observed, worth choosing deliberately:
1. **Inline accordion expand** (MongoDB Compass List/JSON view, RedisInsight key-row expand) — click to expand in place, click again to collapse.
2. **Drill into a new tab** (Compass Table View — nested object cell → new tab showing it as its own table; Beekeeper's FK-click → new tab).
3. **Flat pretty-printed text, no structure** — TablePlus's current approach, and the single most-requested-and-never-shipped gap found in this entire study: **7+ separate open GitHub issues** asking for a Chrome-DevTools-style collapsible JSON tree instead of a text blob ([#2663](https://github.com/TablePlus/TablePlus/issues/2663), [#1558](https://github.com/TablePlus/TablePlus/issues/1558), [#1804](https://github.com/TablePlus/TablePlus/issues/1804), [#1103](https://github.com/TablePlus/TablePlus/issues/1103), [#899](https://github.com/TablePlus/TablePlus/issues/899), [#355](https://github.com/TablePlus/TablePlus/issues/355), [#13](https://github.com/TablePlus/TablePlus/issues/13)).

datagrep's `{3 fields}` chip → detail pane is closer to strategy 1/2 than TablePlus's flat text and should be treated as good instinct. The state-of-the-art reference to steal from later is Compass's **Schema tab**: for a mixed-type field it renders a **clickable horizontal percentage bar per type** (e.g. "20% int32, 80% string"), and picks the summary chart by cardinality (random sample for unique strings, frequency histogram for repeated values, day-of-week/time-of-day pair for dates, min/max/avg length for arrays, an explicit **"40% undefined"** segment for sparse fields rather than silent omission). [Full docs](https://www.mongodb.com/docs/compass/schema/).

**Foreign-key click-to-navigate** — present or requested in nearly every competitor, and explicitly absent from datagrep today:
- DataGrip: clickable FK cells, "Related Rows" panel, F4, Ctrl+Q quick preview, plus **virtual (user-declared) FK support** for engines without real FK constraints.
- Postico: a dedicated FK-value picker widget for browsing the referenced table when *editing*.
- Sequel Ace: a small arrow icon jumps to the referenced table **pre-filtered to the matching row** — when a fork regression reduced this to a plain table-open, a user called it *"one of the most valuable features of Sequel Pro"* and it was restored ([#54](https://github.com/Sequel-Ace/Sequel-Ace/issues/54)). The filtering, not just the navigation, is what people value.
- Beekeeper: click FK → referenced row opens in a **new tab**.
- TablePlus: Quick Look shows FK info but a one-click "jump to referenced row" was **not confirmed** — flagged unverified.

**Row caps / pagination conventions**, for calibrating datagrep's own "truncated" messaging: DataGrip defaults to 500 rows/page (configurable, uncappable); TablePlus 300 rows/page; Beekeeper caps at 20,000 records on-screen with a separate uncapped "download full results" for export; Compass paginates Documents at 25/page (persisted across sessions); RedisInsight explicitly refuses "load everything" for keys. **datagrep's existing 500-row preview cap is squarely in the normal range.**

**Sort-triggers-expensive-query risk**: Postico's accidental-header-click-sort problem on large tables was serious enough to require an explicit cancel/undo mechanism and toggles to disable "always sort" and "exact row counts" ([#221](https://github.com/jakob/Postico/issues/221), [#230](https://github.com/jakob/Postico/issues/230)). datagrep's server-side re-query sort should route through the same cancel-button path as any other query — worth an explicit test.

## 4. Editor

**Run-statement-under-cursor vs. run-all as the primary/default shortcut** is a real, evidenced safety fork:
- Beekeeper Studio binds **Run All** to the primary shortcut and Run Current to the secondary dropdown action — flagged as an active danger by users: *"people often have multiple queries in the same editor tab... This makes it far too easy to accidentally run a previous UPDATE or DELETE"* ([#1679](https://github.com/beekeeper-studio/beekeeper-studio/issues/1679), 24 👍); the reporter switched to Postico 2 over it and notes *"most other SQL editors use the keyboard shortcut & button suggested here"* (i.e., current-statement-as-primary).
- Sequel Ace: Cmd+R = current/selection, Opt+Cmd+R = all — matches the safer convention.
- Postico: ⌘↩ = current/selection, ⌥⌘↩ = all — same safe convention.
- TablePlus makes "which one is default" a **persistent app-level toggle** rather than two always-available modifier-key actions — a different design fork worth knowing about even if not recommended.
- DataGrip: fully configurable granularity (smallest/largest/prompt/whole-script), each independently bindable.

**datagrep's ⌘↵ = statement-under-caret already matches the safety-preferred convention** used by Postico, Sequel Ace, and (implicitly) DataGrip's default. This is a strength — don't change it, and treat Beekeeper's mistake as confirmation, not a reason to add a "run all as primary" mode later without a modifier-key gate.

**Autocomplete**, ranked from most to least sophisticated, all confirmed via docs:
- **DataGrip** (best-in-class): context-aware (reachable-from-caret only), Smart Type Matching, CamelCase/snake_case initialism typing, resolves aliases, and — most notably — **can auto-complete an entire JOIN clause including the ON condition** when two tables share a declared or virtual FK.
- **RedisInsight Workbench**: schema-aware completion specifically for RediSearch index/field names, plus Cmd+Shift+Space inline argument hints for any Redis command.
- **Beekeeper Studio**: deliberately restrained — triggers only after `from`/`join` or `table.`/`alias.`, manual Ctrl+Space otherwise, explicitly designed to not be intrusive.
- **Sequel Ace**: strict left-to-right prefix matching only, **not fuzzy** — an open, repeated complaint ([#328](https://github.com/Sequel-Ace/Sequel-Ace/issues/328)) that `storage_space` won't surface from typing "stsp."
- **TablePlus**: present, but its indexing subsystem is the same one responsible for the catastrophic huge-schema slowdowns in §1 — a direct architectural warning.

Autocomplete quality/reliability bugs are the **#2 most-cited cross-app complaint category** found in this study (see §5) — a half-built, aggressive, or wrong-quoting autocomplete generates more anger than having none. **Recommendation: ship a restrained, manually-triggered version first (Beekeeper's model), lazily indexed per-schema (never eager/whole-catalog, per TablePlus's cautionary tale), before attempting DataGrip-level JOIN-completion.**

**Query history**, universally present in some form, with real variance in quality:
- DataGrip: **two mechanisms** — a per-console history dialog with search, plus a global `database.log` SQL audit trail across every console/data source.
- DBeaver: history exists but users complain it can't be searched by date range with no configurable retention ([#22238](https://github.com/dbeaver/dbeaver/issues/22238)).
- TablePlus: dedicated **History section in the sidebar**, logs every query ever run, double-click to insert, right-click to run/copy/delete.
- Postico: **no discrete history log** — instead, queries are **autosaved per-favorite/per-tab/per-database to disk**, so reopening the same tab restores exactly what was there. A different but valid model.
- Sequel Ace: separate panel, SQLite-backed, but **hard-capped at 100 entries** with an open request to raise it ([#1551](https://github.com/Sequel-Ace/Sequel-Ace/issues/1551)), plus bugs around duplicate entries and mangled multi-line queries.
- Beekeeper: history is **scoped per-connection** explicitly to avoid clutter.
- Compass: a clock-icon "recent queries" menu (up to 30) plus a separate "My Queries" for starred/saved ones.
- RedisInsight: CLI has up-arrow recall (forward-only, no reverse — explicitly noted as a gap in their own release notes); Workbench persists results (up to 1MB) across restarts.

**datagrep has zero query history today** — this is the single most universal gap found in the entire study (every app has *some* form). See §5/§8 for priority.

**A distinctive idea worth flagging for later:** Sequel Ace's **Tab Triggers and Tab Snippets** — saved queries can be given a short typed alias that expands inline, with Tab/Shift-Tab-navigable placeholder cursor stops (TextExpander-style parameterized SQL). This was independently called out as the single most distinctive power-user idea across all eight apps studied.

## 5. Ranked non-negotiable baseline features

Ranked by how often/how strongly the *absence* of the feature (or a broken implementation of it) generated complaints, GitHub issues, or "switched away" posts, across all apps studied. Each cites at least one primary source.

1. **Performance/responsiveness at real scale** (large result sets, huge schemas, huge collections/keyspaces). The single most repeated failure mode, hit independently by DBeaver ([Navigator stalls at 20k+ views, #39861](https://github.com/dbeaver/dbeaver/issues/39861)), TablePlus (100+ schema autocomplete lock-up), MongoDB Compass ([UI unresponsive >30MB collections](https://www.mongodb.com/community/forums/t/mongodb-compass-ui-unresponsive-when-a-collection-size-is-more-than-30mb/206563), 10k-database sidebar taking 60s+), Beekeeper Studio ([~3GB RAM at idle startup, #2894](https://github.com/beekeeper-studio/beekeeper-studio/issues/2894); 18k-table connection crashing at 2.5GB+, [#479](https://github.com/beekeeper-studio/beekeeper-studio/issues/479)), and RedisInsight (SCAN latency amplification, [#6202](https://github.com/redis/RedisInsight/issues/6202)). **datagrep's virtualized 1M+-row grid and lazy tree are direct answers to this — the single strongest architectural bet to keep protecting.**
2. **Autocomplete quality/reliability.** Wrong quoting of columns/tables with capitals/dots/spaces, autocomplete wiping a whole line on JOIN, not firing on UPDATE, being too aggressive to dismiss — a cluster of Beekeeper Studio issues ([#1720](https://github.com/beekeeper-studio/beekeeper-studio/issues/1720), [#3409](https://github.com/beekeeper-studio/beekeeper-studio/issues/3409), [#327](https://github.com/beekeeper-studio/beekeeper-studio/issues/327), [#2732](https://github.com/beekeeper-studio/beekeeper-studio/issues/2732)) that reads as a recurring genre, not a one-off. A broken autocomplete is worse than none.
3. **Connection stability / reconnect handling**, especially SSH tunnels. Sequel Ace: silently reconnects to the *local* DB instead of remote after sleep ([#429](https://github.com/Sequel-Ace/Sequel-Ace/issues/429)), nightly connection drops that never auto-recover ([#1442](https://github.com/Sequel-Ace/Sequel-Ace/issues/1442)). RedisInsight: SSH tunneling flatly unsupported for cluster DBs ([#1831](https://github.com/redis/RedisInsight/issues/1831), [#2670](https://github.com/redis/RedisInsight/issues/2670)), repeated auth-method failures ([#1874](https://github.com/redis/RedisInsight/issues/1874)). This class of bug risks silent data-corruption scares (editing what you think is remote but is local).
4. **Dark mode correctness bugs — not aesthetics, actual unreadable UI.** TablePlus: connected-database label invisible, light-on-light ([#614](https://github.com/TablePlus/TablePlus/issues/614)); doesn't follow macOS auto light/dark ([#1782](https://github.com/TablePlus/TablePlus/issues/1782)). DBeaver: five-plus open dark-mode issues including black-on-black text in preferences. Sequel Ace: invisible NULL label ([#1415](https://github.com/Sequel-Ace/Sequel-Ace/issues/1415)), hardcoded white query-editor background even in dark mode ([#145](https://github.com/Sequel-Ace/Sequel-Ace/issues/145)).
5. **Licensing/pricing friction that reads as broken trust, not a business decision.** TablePlus: free tier capped at 2 tabs/2 windows/2 filters (blocks the exact side-by-side-table-comparison workflow a light client should excel at); license silently reverting to free-tier hours after activation ([#3405](https://github.com/TablePlus/TablePlus/issues/3405)); trial nag popup reportedly "every minute or so." **Not directly applicable to datagrep's UI, but a reminder that trust erosion from small, silent failures compounds.**
6. **Startup time / resource weight.** DBeaver's JVM/OSGi startup is the most consistently repeated complaint across GitHub/HN/community sources; DataGrip is also described as slow-to-start and memory-heavy in real reviews (undercutting its own "light" self-image); JetBrains ships a first-party "High memory consumption" troubleshooting doc. **Directly relevant to datagrep's "free and light" positioning — worth a real benchmark, not just an assumption of superiority.**
7. **Query history depth/searchability/scope.** DBeaver can't easily search history by date with no retention control ([#22238](https://github.com/dbeaver/dbeaver/issues/22238)); HeidiSQL users want history decoupled from "which database was I even connected to" ([#1142](https://github.com/HeidiSQL/HeidiSQL/issues/1142)); Sequel Ace hard-caps at 100 entries. Even where present, history quality is a recurring friction point — see §8, this is datagrep's single biggest structural gap.
8. **Foreign-key / related-row navigation.** Lower complaint *volume* but high *value-when-present* — Sequel Ace's restored FK-arrow was called "one of the most valuable features of Sequel Pro." Reads as quiet abandonment risk (people don't complain loudly about a missing feature they assume doesn't exist) more than an angry-review generator.
9. **Inline cell editing correctness/safety.** Lower complaint volume, high severity when it fails: Beekeeper Studio cannot safely edit tables without a primary key ([#1532](https://github.com/beekeeper-studio/beekeeper-studio/issues/1532), open, 23 comments); a build-guide from QoreDB explicitly warns that a naive implementation can update the wrong row (guessed PK) or clobber concurrent edits across all displayed columns. This is a "designed right or don't ship it" feature, not a checkbox.
10. **NULL vs. empty-string rendering/export correctness.** See §3 — five separate apps have shipped bugs here. datagrep is currently ahead; keep it that way through dark-mode and future-export QA.
11. **Nested JSON/document tree rendering.** TablePlus's 7+ duplicate open feature requests (§3) is the clearest signal that flat pretty-printed JSON is felt as broken, not just plain.
12. **Run-all-as-default-shortcut danger.** Beekeeper's [#1679](https://github.com/beekeeper-studio/beekeeper-studio/issues/1679) — confirmed as an active data-safety complaint, not hypothetical.
13. **Partial/capped results must visibly announce their own incompleteness.** RedisInsight's Tree View builds folders only from already-scanned keys — namespaces not yet reached simply don't appear, falsely implying they don't exist ([#4510](https://github.com/redis/RedisInsight/issues/4510), [#6311](https://github.com/redis/RedisInsight/issues/6311)). The opposite instinct — Compass's explicit "40% undefined" segment — is the right one.

## 6. Professional polish touches

Things praised unprompted, worth deliberately emulating:

- **Connection color as a large, always-visible surface** — full tab background (Compass), status-bar tint (Beekeeper), not a small dot (Sequel Ace's downgrade caused a user revolt). Show it even with a single connection open.
- **Unified structure editor** — Postico's columns+indexes+constraints-in-one-view, explicitly named as a delight in App Store reviews.
- **Staged-edit diff-before-commit** — Beekeeper Studio color-codes pending row edits (green=new, red=deleted, orange=updated) with explicit **Apply**/**Reset** buttons, functioning as a safety net before any write actually lands. This is the direct answer to "how do we make inline editing safe" from §5 item 9.
- **DDL three-way diff preview** — Postico shows current / pending / resulting DDL side-by-side when a structure change is uncommitted.
- **Rich "copy as" menus straight from the grid** — TablePlus: Plain text, JSON, HTML, Markdown, CSV, CSV+header, SQL Insert, all from a grid-selection right-click. datagrep's existing cell/row-JSON/row-TSV/column/selection copy menu is already in this spirit — good.
- **Background, non-blocking export** — DBeaver's Data Transfer wizard runs in the background so the app stays usable during a large export; Compass's export explicitly warns "CSV is not a suitable backup format, it loses type information."
- **Autosaved, persistent scratch queries** — Postico restores exactly what was in a given tab/favorite/database combination on reopen, without an explicit save action.
- **Bulk-action preview counts** — RedisInsight's Bulk Actions shows a **live count of matching keys before you commit** to a delete/expire, and a Tree View folder-delete pre-fills the matching pattern automatically — turns a scary bulk operation into a reviewable one.
- **Command-palette-style global fuzzy jump** — DataGrip's Search Everywhere, TablePlus's Open Anything, Postico's ⌘P, Beekeeper's ⌘P — near-universal among the polished apps, notably absent from RedisInsight and Sequel Ace.
- **Built-in SQL formatter** — Postico bundles pgFormatter rather than requiring an external tool.
- **Keyboard-first vocabulary shared between editor and grid** — rainfrog (TUI) applies the *same* vim-style movement/selection keys to both the SQL editor and the results grid rather than two different keyboard languages; Harlequin's fully remappable keymap config is the natural next step once a keyboard-first baseline exists. Directly relevant given datagrep already emphasizes keyboard cell navigation.

## 7. What people actively dislike, per app

- **DataGrip**: memory footprint undercutting its own "not-DBeaver" positioning (~1.7GB for one connection cited in a G2 review, first-party "high memory consumption" troubleshooting doc exists); a named-and-shamed table/field structure editor called "painfully slow and unintuitive"; subscription pricing and a free tier that explicitly can't be used for any paid work; real regressions even in a mature paid product (results grid not rendering after a version update, crash-on-OOM losing unsaved data-source config).
- **DBeaver**: startup time (JVM/OSGi, worse under antivirus scanning) is the most consistently repeated complaint across every source type checked; memory growth is a **multi-year, multi-version pattern** (1MB/2sec leak in 2017 through 5GB-on-large-scripts in 2025); dark theme correctness has been an open, unresolved complaint for years (root cause: Eclipse SWT's weak native theming); general clutter with many connections; steep Community→Lite→Enterprise→Ultimate feature-gating for NoSQL/AI/Excel-export/SSO.
- **TablePlus**: catastrophic performance collapse at schema scale (§1); the most-requested-and-never-shipped nested JSON tree view; trial nag-popup frequency; license validation bugs (silent expiry); no manual rollback button in the UI; free-trial tab/window/filter caps frustrate evaluators before they even see a paywall.
- **Postico 2**: NULL-vs-empty-string default confusion; no permission/role management UI at all (a named blocker for one prospective enterprise adopter); accidental-header-click-sort historically triggered runaway queries on large tables; one secondhand "bland/monolithic" aesthetic critique; Postgres-only scope.
- **Beekeeper Studio**: RAM usage with hard numbers (~3GB at idle startup before settling to ~1.3–1.4GB, still more than VS Code with extensions); an 18k-table connection loading everything into memory and crashing; multiple "extremely slow"/high-CPU issues; a specific regression where opening a table over SSL Postgres took ~15 seconds versus milliseconds for the equivalent raw query, isolating the overhead to the client layer, not the DB; upgrade regressions that broke basic connectivity for all connections.
- **Sequel Ace**: buggy dark mode (invisible NULL, hardcoded backgrounds); severe **syntax-highlighting typing lag** — keystrokes falling 10+ seconds behind once several queries are in the editor, fixable only by disabling highlighting entirely; sustained 57–100% idle CPU with a single connection; window dropping behind other apps after any refresh; the maintainers explicitly declining Postgres support (193-reaction feature request, by far the most-reacted issue found in this entire study) because they need to "stabilize with MySQL" first.
- **MongoDB Compass**: UI freezing on large documents/collections (~30MB+, or ~4.4M-document collections) with no published fix as of March 2025; a known bug specifically when switching between JSON view and other document views; the aggregation pipeline builder's learning curve for beginners once pipelines chain multiple stages (41 open improvement ideas on their feedback forum is itself a friction signal).
- **RedisInsight**: the 10,000-key cap on Database Analysis and Tree View producing silently incomplete folders (§5 item 13); SCAN-over-latency amplification is architecture, not user error, per the maintainers' own benchmark; no connection color-coding; no bulk export of key data; Electron packaging fragility on Linux (ARM segfaults, RPM install failures on RHEL derivatives).

## 8. Gap analysis vs. datagrep current state

datagrep's current state, as given: sidebar tree (connections → database → schema → table/view → column, lazy per level, Redis prefix-gated, engine logos, filter box, hover states); double-click → `SELECT * LIMIT 500`, right-click → "Preview 500 Rows"; a schema detail pane in active development (columns, indexes, stats); a virtualized NSTableView grid (1M+ rows, hover, rich copy menu, rectangular selection, ⌘C-as-TSV, keyboard nav, server-side sort, resize/reorder, distinct NULL/empty/ABSENT rendering, `{N fields}` nested-value chip); an NSTextView editor (syntax highlighting, named per-connection tabs, ⌘↵ runs statement-under-caret, block directives); a status bar with cancel. Explicitly absent: query history UI, ER diagrams, data export UI beyond CLI, foreign-key navigation, autocomplete, multiple result tabs, row-number column, inline cell editing.

### Strengths to preserve (confirmed ahead of or aligned with the field)

- **Distinct NULL / empty-string / ABSENT rendering** — no competitor studied cleanly nails all three; several have shipped real bugs here (§3, §5 item 10). QA this explicitly under dark mode and, later, under CSV export before either ships, since that's exactly where DBeaver, Beekeeper, and Sequel Ace broke it.
- **Lazy per-level tree loading** — directly avoids TablePlus's worst-in-class failure (eager whole-catalog autocomplete indexing blocking query execution) and matches DBeaver's/RedisInsight's winning pattern (paginate/lazily load, don't eagerly preload). See the one remaining gap below (partial-view visibility).
- **⌘↵ runs statement-under-caret as the primary shortcut** — matches the safety-preferred convention (Postico, Sequel Ace) and directly avoids Beekeeper's documented danger of defaulting to Run All ([#1679](https://github.com/beekeeper-studio/beekeeper-studio/issues/1679)).
- **Data-first on table open** (`SELECT * LIMIT 500` on double-click) — matches the majority pattern (Postico, TablePlus, DataGrip's data-grid default, Beekeeper) rather than DBeaver's/Compass's structure-first default.
- **Redis prefix-required listing** — directly validated by RedisInsight's own maintainers, who benchmarked that SCAN cost is dominated by round-trips, not match count, and who actively refuse to add a "scan everything" button for exactly this reason ([#6202](https://github.com/redis/RedisInsight/issues/6202), [#526](https://github.com/redis/RedisInsight/issues/526)).
- **Rich grid copy menu** (cell/row-JSON/row-TSV/column/selection) already matches the spirit of TablePlus's most-praised "copy as" feature.

### P0 — do next (highest cited demand, or safety-critical)

| Gap | Who has it | Why P0 | Difficulty given datagrep's architecture |
|---|---|---|---|
| **Query history UI** | Every single app studied has some form (DataGrip: two mechanisms; TablePlus: dedicated sidebar section; Postico: autosave-as-history; Sequel Ace, Beekeeper, Compass, RedisInsight all have one) | The single most universal gap found in this entire study — zero exceptions across 8 primary apps | **Low-medium.** No write-path risk (unlike inline editing) — log every executed statement + connection + timestamp + duration/row-count to a local store, surface as a sidebar panel with search. Should be the fastest, lowest-risk, highest-visibility win available. |
| **Connection color-coding** | Every app except RedisInsight; the one app that shrank it (Sequel Ace) got sustained user backlash | Universally treated as the primary defense against "ran a DROP on prod" accidents — directly named in datagrep's own current-state list as absent | **Low.** A color field on the connection model plus a tinted UI surface (tab background and/or status-bar band — must be large and always-visible per Sequel Ace's lesson, not a small dot). Engine-logo infrastructure already exists to build alongside. |
| **Row-number column** | DataGrip confirmed (clickable, selects whole row); a standard convention in virtually every spreadsheet-like grid | Cheap, universal, and directly useful for referencing specific rows in bug reports/conversation | **Low.** NSTableView already virtualizes 1M+ rows — add a pinned first column showing row index. |
| **Foreign-key click-to-navigate (with pre-filtering, not just table-open)** | DataGrip (Related Rows/F4/Ctrl+Q, plus virtual FK support for FK-less engines), Postico (dedicated FK picker), Sequel Ace (called "one of the most valuable features of Sequel Pro"), Beekeeper (opens in new tab) | High value-when-present even though it's a quiet-abandonment risk rather than an angry-review generator; the schema pane currently being built is already modeling constraint/index metadata — build this while that data model exists rather than retrofitting later | **Medium.** Needs FK metadata (likely already surfacing from the in-flight schema pane work), a "referenced row(s), filtered" query generator, and a navigation UX decision (new tab vs. inline, per §3's three observed strategies). |
| **Inline cell editing, designed around a staged-edit review-before-commit model** | Literally every competitor studied (Postico, TablePlus, DataGrip, DBeaver, Beekeeper, Sequel Ace, Compass, RedisInsight) — the only true universal with zero exceptions | The single most "non-negotiable" feature in the whole study by raw count of competitors having it, despite datagrep's grid otherwise being very capable | **High.** Requires a Rust-engine write path per supported engine, safe PK detection (Beekeeper's own open issue on PK-less tables is the cautionary tale, [#1532](https://github.com/beekeeper-studio/beekeeper-studio/issues/1532)), and a GUI staged-edit affordance. **Design directly off Beekeeper's green/red/orange + Apply/Reset pattern** (§6) rather than committing writes immediately per keystroke/cell-exit, and explicitly guard against QoreDB's documented failure modes (updating on a guessed PK, clobbering concurrent edits across all displayed columns). This is the most architecturally demanding item on this list but also the most-cited absence — flag prominently to implementation agents even though it will take the longest. |

| Gap | Notes |

| **Basic, manually-triggered autocomplete** (table/column names, Ctrl+Space-style) | Autocomplete quality is the #2-ranked cross-app complaint (§5) — a bad implementation is worse than none. Ship Beekeeper's restrained model (trigger after `FROM`/`JOIN` or `alias.`, manual otherwise) first; DataGrip-level JOIN-clause completion is a follow-on. **Must be lazily indexed per-schema, never eager/whole-catalog** — this is exactly the design mistake behind TablePlus's worst failure mode (§1). | **Multiple result tabs** | TablePlus splits results into tabs; DataGrip supports multiple (configurable reuse); Beekeeper's FK-navigation opens a new tab. Mostly a SwiftUI state-management concern rather than deep engine work — medium difficulty. |
| **Global fuzzy "open anything" jump (⌘P-style, across all connections/schemas/tables at once)** | Near-universal among the polished apps (DataGrip Search Everywhere, TablePlus Open Anything, Postico ⌘P, Beekeeper ⌘P) and notably a differentiator against RedisInsight/Sequel Ace, which lack it. Low-medium difficulty. |

### One positioning note, not a UI gap

DataGrip and DBeaver's own users repeatedly describe them as memory-heavy and slow to start (§7) — this directly undercuts the "DataGrip but free and light" pitch *if datagrep can't verifiably beat them on resource usage*. Recommend an actual head-to-head RAM/startup-time benchmark (datagrep vs. DataGrip vs. DBeaver vs. Beekeeper Studio, which has the most damning documented numbers at ~3GB idle) before leaning hard on "light" in any external-facing copy — it should be provably true, not just architecturally plausible.

## Appendix A: Secondary apps, distinctive patterns only

- **Querious** ($25 one-time, macOS-native MySQL): sidebar groups objects into per-type folders (a middle ground between a schema tree and a flat list); optimizes connection-sharing across tabs on the same server so opening N tabs doesn't multiply connection/memory cost — worth doing in the Rust engine layer. [Source](https://www.araelium.com/querious/why)
- **Navicat** (paid, cross-platform, feature-heavy): the reference for a "full" ER diagram feature if datagrep ever builds one — reverse-engineers a DB into a diagram (Crow's Foot/UML/IDEF1x notations), then a **"Synchronize to Database"** diff view generates a reviewable sync script rather than silently auto-applying changes. Connection color-coding + folder grouping in its navigation pane. [Source](https://www.navicat.com/en/products/navicat-data-modeler)
- **TableCruncher** (GPLv3, CSV-focused): no sidebar at all — for pure local-file workflows, users don't seem to want or need a schema tree. Opens 2GB+/15M-row CSVs in seconds without Electron overhead; explicit multi-encoding auto-detection (UTF-8/16LE/16BE/Latin-1/Windows-1252) is called out as a named feature, worth being explicit about rather than silently guessing encodings. [Source](https://github.com/Tablecruncher/tablecruncher)
- **Outerbase** (web-based, AI-flavored): one-click chart generation from a result set, and plugin-able cell/column renderers (render a JSON column as a mini tree, a URL column as a link chip) — worth considering for datagrep's NSTableView cell rendering even without the AI angle. [Source](https://outerbase.com/)
- **Antares** (Electron/Vue, open source): explicit anti-clutter design philosophy ("no hundreds of tiny buttons, nested tabs, or submenus"); built-in fake-data-filler for seeding test tables; a searchable 1000-query history explicitly marketed as a selling point — further evidence deep, searchable history is a baseline expectation, not a nice-to-have. [Source](https://github.com/antares-sql/antares)
- **Harlequin** (Python TUI): keyboard-navigable schema tree, F1 in-app contextual help, fully remappable keybindings via config file — the natural next step once datagrep's existing keyboard-first grid navigation matures. [Source](https://github.com/tconbeer/harlequin) (note: exact keymap specifics were not independently fetchable in this pass — secondhand via search summaries only)
- **rainfrog** (Rust TUI, Postgres): the most directly relevant keyboard-first reference — applies the **same** vim-style movement/selection vocabulary (j/k/h/l, v/V select, y yank, g/G top/bottom) to *both* the SQL editor and the results grid rather than two different keyboard languages, plus `/`-to-fuzzy-filter the table list. [Source](https://github.com/achristmascarl/rainfrog)

## Research method notes

Four parallel research passes covered: (1) Postico 2 + TablePlus, (2) DataGrip + DBeaver, (3) Beekeeper Studio + Sequel Ace + MongoDB Compass + RedisInsight, (4) secondary apps + cross-app complaint mining. Sources preferred official docs, GitHub issue trackers (sorted by reactions/comments where possible), release notes, and community forum threads over marketing copy. Every claim in this document traces to a cited source; anything the underlying research could not verify (e.g., DataGrip's exact NULL cell styling, Sequel Ace's default table-click tab, Harlequin's precise keymap) is called out inline as unverified rather than presented as fact. Two known research gaps: live Reddit thread content was hard to retrieve directly (search kept surfacing SEO/comparison pages instead of actual reddit.com threads — GitHub issues ended up being the stronger, more verifiable evidence base for the ranked list in §5), and a few Hacker News comment threads returned HTTP 429 and could only be characterized via search-result summaries rather than direct quotes.
