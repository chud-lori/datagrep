# Code of Conduct

## The short version

Be decent. Assume the person you are talking to is acting in good faith, and
argue about the code rather than about each other.

## What is expected

- Be direct about technical problems and kind about people. "This query plan is
  wrong because X" is welcome; "you clearly did not read the docs" is not.
- Accept that a maintainer may say no. This project deliberately keeps a small
  dependency list, a streaming architecture, and a narrow scope — a rejected
  idea is usually about fit, not about you.
- If you are wrong, say so and move on. Nobody here keeps score.

## What is not acceptable

- Harassment, insults, or personal attacks, in issues, pull requests, commit
  messages, or anywhere else this project is discussed.
- Sexualised language or imagery, and unwelcome attention of any kind.
- Publishing anyone's private information without their explicit permission.
- Deliberately derailing discussions, or persistently reopening a decision after
  it has been made and explained.

## Security issues are different

Do not report vulnerabilities in public issues, and do not test them against
infrastructure you do not own. See [SECURITY.md](SECURITY.md) for private
reporting.

## Enforcement

Report a problem privately to the maintainer through
[GitHub](https://github.com/chud-lori) — the same private channel described in
[SECURITY.md](SECURITY.md) works for this too.

This is a one-maintainer project, so expect a human response rather than a
process: reports are read, kept confidential, and acted on. Depending on
severity that may mean a request to edit a comment, a warning, or a block from
the repository. Repeat or severe behaviour is met with a permanent block on the
first report — there is no strike count.

If the problem is with the maintainer's own conduct, say so plainly in the
issue or pull request where it happened. Being the only maintainer is not a
defence.

## Scope

This applies in the repository — issues, pull requests, discussions, commit
messages, code comments — and anywhere someone is representing the project.
